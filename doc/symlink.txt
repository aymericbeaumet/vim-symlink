==============================================================================
1. Introduction                                           *symlink-introduction*

{vim-symlink}{1} automatically follows symlinks in Vim and Neovim. When you
open a symlink, the buffer uses the resolved target path. This lets plugins
such as vim-fugitive discover the target's Git repository. The symlink stays
in place, and your working directory does not change.

In Neovim, a native Lua implementation is used. In Vim, an equivalent
VimScript implementation is used. Both implementations share the same features
and behavior.

The plugin loads automatically at startup; no setup call is needed. Plugin
managers should load it eagerly so it can handle the first file you open.

Resolution runs on |BufReadPost| for readable, normal file buffers. Chained
symlinks and files inside symlinked directories are supported. If the target
already has a buffer, that buffer is reused, preserving its unsaved edits.
Splits, tabs, read-only mode, and diff mode are supported.

Special buffers and unreadable or broken links are left to the editor. New
files in symlinked directories retain the editor's normal behavior. Resolving
a link changes the buffer's path; disable the plugin before opening a file
if your workflow needs the link's name or location.

                            {1}: https://github.com/aymericbeaumet/vim-symlink

==============================================================================
2. Configuration                                         *symlink-configuration*

You can configure this plugin through the following global variables.

------------------------------------------------------------------------------
*g:symlink_loaded*

Set this before plugin loading to prevent the plugin from loading. The
presence of the variable is checked, regardless of its value.
>
    let g:symlink_loaded = 1
<

------------------------------------------------------------------------------
*g:symlink_enabled*

Defaults to 1. Set to 0 to disable resolution for subsequent file reads
without unloading the plugin. Set to 1 to enable it again. This does not
rename buffers that have already been resolved:
>
    let g:symlink_enabled = 0
<
In Lua, use vim.g.symlink_enabled = 0.

------------------------------------------------------------------------------
*g:symlink_redraw*

By default vim-symlink will make sure to redraw the screen after a symlink
has been followed. This can cause the screen to flicker. To prevent this, set
this option to 0:
>
    let g:symlink_redraw = 0
<

==============================================================================
3. Events                                                     *symlink-events*

vim-symlink fires a |User| autocommand after resolving a symlink:
>
    autocmd User SymlinkResolve echomsg "Symlink resolved!"
<
